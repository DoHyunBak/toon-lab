# 제작 트러블슈팅

## 그림과 식자는 정리됐지만 이야기가 설득되지 않는다

**증상:** 사건·만남·제안이 연달아 나오지만 인물이 왜 그 선택을 하는지 읽히지 않는다.
작화 검수 통과와 별개로 사용자가 개연성 문제를 제보한다.

**원인:** 기존 검수는 원고를 충실히 그렸는지를 확인했지만 원고 자체의 동기·인과를
충분히 검토하지 않았다. 장면의 좋은 대사와 인기 장치가 인물 선택의 이유를 대신했다.

**확인:** 그림 없이 원고를 읽고 선택마다 앞의 원인을 지목한다. 간단한 대안으로 상황을
피할 수 있는데도 설명 없이 어려운 선택을 한다면 핵심 결함이다. 장면 시작/끝의 정보와
감정이 같은지도 확인한다. 그림 검수 점수를 스토리 평가로 사용하지 않는다.

**수정:** 해당 원고의 확장 작화를 멈추고 기획→인물 목표→결말까지의 인과→회차→장면을
역순/정순으로 대조해 다시 쓴다. 기존 거절본은 이력에 보존하며 최신 완성본에서 제외한다.
[스토리 검토 양식](STORY_REVIEW_TEMPLATE.md)에 문제와 실제 수정 구간을 연결하고 남은 핵심
문제가 없어야 새 원고로 진행한다. 양식은 수동 공정이며 재미를 보장하는 자동 게이트가 아니다.

## 사용자가 지정한 썸네일과 본편 인물이 달라진다

**증상/원인:** 제공된 시각 기준을 단순 참고로만 취급하고 머리·의상·얼굴 비례를 새로 설정하면, 원고 사건이 같아도 다른 작품처럼 보일 수 있다. 이미지의 전송 권한이 미확인이라는 이유로 시각적 의도까지 임의로 바꾸지 않는다.

**수정/재발 방지:** 현재 사용자 지시가 외형 기준을 지정했는지 먼저 확인하고, 해당 파일을 직접 열어 머리·표식·의상·얼굴 비례·선·채색을 텍스트 불변 조건으로 기록한다. 관찰 기준과 생성 모델의 실제 이미지 입력 허용은 별도로 판단한다. 텍스트 전용이면 이미지 자체를 첨부하지 않고 그 조건을 사용한다. 첫 한 컷을 원본과 실제로 대조한 뒤 확대하며, 불일치가 발견된 방향의 일괄 생성을 멈춘다. 거절된 전체 시퀀스는 새 기준으로 승인된 것처럼 재사용하지 않는다.

**검증 한계:** 외형 항목 일치와 작화 전체 일치는 다르다. 옷·머리만 맞아도 피부 광택·얼굴 비례·선·재질이 달라질 수 있으므로 실제 비교와 사용자의 작화 승인을 구분한다.

## 의도한 다중 장면과 단일 컷 지시가 충돌한다

**증상/원인:** 한 원화에 여러 장면을 명시해도 준비 브리프의 고정 문장이 단일 컷을 요구했다. 상위 장면 수와 하위 브리프를 서로 다른 계약으로 작성한 탓이다.

**수정/재발 방지:** 준비 브리프도 명시된 장면 수로 분기하며 단일 장면은 기존 표현을 유지한다. 실제 다음 실행 프롬프트에 의도한 여러 장면 지시가 있고 반대 단일 컷 문장이 없는지 회귀검사한다. 생성 파일 수와 실제 이야기 장면 수는 따로 기록한다. 프롬프트 일치 검사는 실제 생성된 장면 수·단서·표현 품질의 검수를 대체하지 않는다.

## 같은 줄의 풍선 읽기 순서가 뒤집힌다

**증상/원인:** 몸체 중심 높이를 정렬 키로 쓰면 높이가 다른 나란한 풍선의 순서가 바뀐다.

**수정/재발 방지:** 현재 한국어 읽기 순서는 몸체 위쪽 변, 그다음 왼쪽 변으로 검사하고 같은 위쪽 변/다른 높이의 회귀 입력을 둔다. 실제 위치와 화자·꼬리는 화면에서 별도로 확인한다. 프로젝트 전용 배치 보조 함수의 경계 검사와 원화·식자 관찰을 구분한다.

제작 과정의 실패를 다시 만들지 않기 위한 독립 노트다. 비공개 작품 자료와 원문 대화를 복사하지 않고, 재사용 가능한 원인·공정·코드 계약만 정리했다. [결정 기록](WORKFLOW_DECISIONS.md), [제작 운영](PRODUCTION_RUNBOOK.md), [에이전트 이미지 제작 절차](AGENT_IMAGE_WORKFLOW.md)를 함께 읽는다. 중단된 실행의 현재 상태 복구는 [세션 연속성](SESSION_CONTINUITY.md)을 따른다.

다음 상태를 구분한다.

- **사용자 제보:** 품질 문제를 알리는 유효한 신호다. 코드 통과 기록으로 반박하지 않는다.
- **감사 관찰:** 보존된 특정 입력·산출물·상태에서 확인한 사실이다. 전체 회차나 전체 작업시간으로 확대하지 않는다.
- **현재 구현 확인:** 아래 코드와 테스트가 검사하는 동작이다. 실제 원화 품질·생성 성능·권리를 인증하지 않는다.
- **미검증:** 새 원화 비교, 전체 수정 범위, 실제 장치 실행이나 보관 readback이 아직 필요한 상태다.

## 그림체가 기준 회차에서 달라진다

**제보와 관찰:** 같은 그림체를 유지하라는 요청 뒤에도 차이가 반복됐고, 기준 원화와 새 시험 컷을 비교한 뒤 제한된 자체 원화 참조 예외가 생겼다. 이는 해당 스타일 시험의 승인 범위이며 회차 전체 승인이나 모든 모델에 대한 참조 허용이 아니다.

**가능 원인:** 텍스트만 반복하면 인물 비례·재질·조명·형태가 고정된다고 보장할 수 없다. 참조 한 장을 쓰더라도 그 장면의 소품·구도·배경이 새 장면에 따라올 수 있다. 과거 감사에서 이런 내용 유입의 정황이 관찰됐지만 인과 효과를 대조 실험으로 수치화하지는 않았다.

**처리:** 먼저 현재 입력 모드와 허용 도구·이미지를 확인한다. 기준 원화와 시험 한 컷을 실제로 열어 형태·입체감·재질·색·조명을 비교하고 새 장면의 사건·소품이 유지됐는지 본다. 맞으면 짧은 연결 시퀀스로 확대한다. 맞지 않으면 모델/그래프/입력 방법을 작은 시험에서 바꾼다. 후속 컷이나 거절 후보를 무단 참조로 추가하지 않는다.

**구현/한계:** 카탈로그·권한·해시와 실제 참조 선언은 검사하지만 그림체 일치 점수를 자동 발급하지 않는다. 기존 자체 원화 예외는 허용된 이미지 도구와 입력 범위에 결합되어 있다. [자체 원화 계약](../../src/owned_episode_reference.py) · [검사](../../tests/test_owned_episode_reference.py)

## 장소·소품·행동이 컷마다 바뀐다

**감사 관찰:** 회차 전체 장소와 구조가 최초 prompt에 빠지고, 결과를 본 뒤 같은 장소 오류를 컷마다 따로 수정한 사례가 있었다. 문·조명·소품 상태의 기준도 생성 뒤에 정리되어 연쇄 교체가 발생했다.

**원인:** 원고 문장만으로 매 컷에 필요한 공통 상태가 전달됐다고 가정했다. 이전 컷에서 확인한 결함을 다음 최초 입력에 반영하지 않았다.

**처리:** 공통 `setting/visual_invariants`와 장면별 `source_action/staging/prop_state/protected_subjects`를 작성한다. 원고 해시·ID·순서와 결합해 실제 prompt에 들어갔는지 확인한다. 회차 경계와 직전·다음 컷도 비교한다. 비어 있지 않은 필드라는 이유로 상태 내용을 통과시키지 않는다.

공통 소품 수정이 일부 페이지에만 붙고 최초 전경이나 연결 삽입컷에는 빠지는지도 확인한다. 실제 전송할 모든 관련 prompt를 나란히 검사하되, 수량·열림 상태·배치가 사건 중 바뀌면 초기 상태를 일괄 덮어쓰지 않는다. 공통 불변 조건과 장면별 상태를 분리한다. 이 텍스트 검사는 생성 결과의 시각적 일치를 보증하지 않는다.

한 소스 페이지의 일부 컷만 통과했으면 통과한 컷과 거절한 컷을 각각 기록한다. 부분 반입에는 그 소스를 실제로 생성한 prompt를 연결하고, 다음 시도의 수정 prompt를 과거 결과의 입력으로 기록하지 않는다. 불량 컷을 교체한 뒤 앞뒤 상태와 식자 결과를 다시 본다.

**현재 구현:** 원고 변경, 누락·재정렬, 원문 사건 불일치와 필수 필드 누락을 거절한다. 새 context를 쓰는 작업은 현재 workflow evidence에 결합되어야 한다. 실제 공간·연속성은 관찰 대상이다. [컴파일/결합](../../src/production_control.py) · [검사](../../tests/test_production_control.py) · [다음 단계](../../src/operations.py)

## 수정할수록 prompt가 길고 모순된다

**감사 관찰:** 이전 구도 지시 뒤에 반대되는 수정 지시가 누적되어 현재 실행 입력에 여러 수정 블록이 경쟁했다.

**처리:** 과거 시도와 거절 이유를 별도 이력에 보존하고 현재 prompt에는 최신 수정 하나만 둔다. 수정은 무엇을 바꾸는지와 이유를 구체적으로 적는다. 같은 분류의 실패가 이어지면 방법·구도·표현을 재평가한다.

**현재 구현:** 수정 정규화와 반복 실패/재계획 검사가 있다. unresolved replan은 명시적 컷 선택과 자동 다음 컷 선택 모두에서 차단된다. 해제에는 기록 해시, 달라진 현재 prompt 해시와 변경 전략이 필요하다. [제어](../../src/production_control.py) · [batch 정규화](../../tools/compile_production_batch.py) · [검사](../../tests/test_production_control.py) · [차단 경로 검사](../../tests/test_operations.py)

**수동 경계:** 공개 범용 경로에는 모든 거절을 자동 분류해 attempt/replan 파일을 만드는 wrapper가 없다. 실제 관찰과 분류를 기록하고 현재 해시에 결합해야 한다. 검사 함수를 제공한다는 사실과 기록·차단 공정이 자동 실행된 사실을 구분한다. 이미 원인을 안다면 두 번 실패할 때까지 기다리지 않는다. 새 전략의 시각적 효과는 별도 검수한다.

## 장면 배치가 기준 회차의 흐름과 다르다

**제보:** 작화 비교가 통과한 뒤에도 장면 배치가 기준 회차와 다르다는 피드백이 있었다. 그림체 기준과 연출/배치 기준은 별개다.

**원인 후보:** 원화들을 같은 폭·같은 여백으로 나열하거나 이전 회차 profile을 장면 목적 검토 없이 복사했을 수 있다. 이것이 모든 배치 차이의 유일 원인이라고 단정하지 않는다.

**처리:** 장면별 역할·시간층·연결/전환·강조·정지 지점을 명시한다. 원고 순서와 전체 범위를 유지하면서 폭·정렬·여백을 계산하고 실제 세로 화면의 여러 정지 위치를 본다. 구도 자체가 틀렸는지, 배치만 틀렸는지를 먼저 분리해 필요한 단계만 수정한다.

**현재 구현:** 의미 입력에 따른 배치, 원본 비율/범위 보존, 선택적인 모바일 높이 예산과 전환 검사가 있다. 독자 시선이나 미적 품질을 자동 판정하지 않는다. [배치](../../src/layout_policy.py) · [합성](../../src/layout_composer.py) · [검사](../../tests/test_layout_policy.py)

## B/C 크기는 맞는데 말풍선이 장면을 가린다

**제보와 관찰:** 특정 회차의 말풍선 품질 불만이 있었고, 별도 감사에서는 다른 회차의 C 선택 집합과 효과음 좌표를 복사한 실제 분기, 눈 부근을 덮는 배치, 뒤늦게 대부분 대사를 바깥 띠로 옮긴 우회가 확인됐다. 제보 대상 전체 화면을 새로 전수 검수했다는 증거는 없으므로 문제 전체가 해결됐다고 기록하지 않는다.

**원인:** 실측 몸체 계산과 장면별 배치를 같은 문제로 취급했다. 폰트 크기 계산이 맞더라도 위치·화자·꼬리·시선 순서는 틀릴 수 있다.

**처리:** 현재 원화를 보고 빈 공간과 얼굴·손·행동/단서 보호영역을 작성한다. 장면 중첩은 `art_anchor`와 `protected_art_boxes`로 표시한다. 실측 크기를 유지하고 공간이 부족하면 배치·컷 여백을 수정한다. 모든 대사를 바깥 띠로 밀거나 글자를 줄이는 것을 기본 해법으로 삼지 않는다. 식자 문제라면 먼저 기존 원화로 고치고 불필요한 재생성을 피한다.

**현재 구현:** art-relative 좌표 변환은 글자·몸체 크기를 유지하며 보호 영역 충돌과 canvas 밖 배치를 거절한다. B/C renderer는 몸체가 실측 크기와 다르면 오류를 낸다. 보호 영역은 사람이 실제 그림을 보고 작성해야 한다. [실측](../../src/balloon_sizing.py) · [renderer](../../src/editorial_lettering.py) · [좌표](../../src/layout_composer.py) · [B/C 검사](../../tests/test_balloon_sizing_portable.py) · [중첩 검사](../../tests/test_artwork_balloon.py)

## 상세 러프 생성이 제작 시간을 낭비한다

**정정:** 밑작업을 기록하라는 요청을 상세 AI 러프의 반복 생성으로 확대하지 않는다. 필요한 것은 원고를 기준으로 인물·소품·시선·컷·대사 공간을 간단히 정리하는 과정이다.

**처리:** 선 도식이나 텍스트 계획을 만들고 완성 원화의 지시와 관찰 질문에 연결한다. 별도 이미지가 문제를 해결하는 데 필요한지 먼저 확인한다. 수행하지 않은 펜선·채색 단계를 기록용으로 만들어 내지 않는다. 도식 이미지를 생성 모델에 넣는 것은 현재 입력 모드와 별도 허용 범위를 따른다.

**구현/한계:** 텍스트 상태 컴파일과 batch 준비는 모델 호출 없이 수행할 수 있다. 간단한 구도가 완성 원화에 충실히 반영됐는지는 실제 관찰로 확인한다. [준비 도구](../../tools/compile_production_batch.py) · [상태 계약](../../src/production_control.py)

## 후보 파일은 많지만 정식 작업은 미완료다

**감사 관찰:** 별도 전달 후보와 부분 화면 관찰이 존재해도 정식 작업의 output이 비어 있고 현재 원화의 관찰 항목이 미검수로 남은 사례가 있었다. 오래된 상태 파일과 최신 반입 수가 함께 존재해 진행 집계도 달랐다.

**처리:** 현재 작업의 raw·원고·배치 스냅샷·manifest 해시를 기준으로 상태를 읽는다. `apply_layout_policy`의 독립 후보 생성과 factory 검수 결합을 구분한다. 정식 제작은 `build_layout_job`으로 현재 원화와 원고에 결합하고 현재 review 양식의 사본을 작성한다. 결합된 해시를 바꿔 stale 보고서를 통과시키지 않는다.

**현재 구현:** 현재 raw가 아닌 이미지, 다른 대사/description, 누락·재정렬을 배치 결합 단계에서 거절한다. 원화·조립 결과가 바뀌면 기존 검수는 다시 확인한다. 반입·후보·기술 ready·사람 승인·공개 승인은 서로 다르다. ## 시간이 오래 걸리는데 원인별 측정이 없다

**제보:** 4일 8시간에 대한 문제 제기와 100배 단축 목표가 있었다. 4일 8시간은 104시간이지만, 이 전체를 에이전트의 순수 실행시간으로 검증하거나 모델·관찰·대기별로 배분한 것은 아니다. 100배 목표를 단순 환산하면 약 62분이나 달성 기록이 아니다.

**감사 관찰:** 최초 입력의 공통 상태 누락, 충돌하는 수정 누적, 이전 회차 좌표 복사, 결함을 남긴 반입, 정식 검수와 분리된 후보, 작은 변경마다 전체 재조립, 뒤늦은 기록 전송 규격 대응이 재작업을 만들었다. 이는 확인된 공정 결함이며 전체 지연 기여율을 측정한 결과는 아니다. 나중의 환경 준비 대기가 앞선 모든 지연을 설명하지도 않는다.

**제한된 시험:** 내부의 한 46장면 텍스트 준비 시험에서 장소 명시가 46/46에 포함됐고 누적 수정 78개가 컷별 최신 수정 44개로 정리됐다. 단일 context 컴파일 관찰값은 0.564ms였다. I/O·이미지 생성·관찰 QA·외부 적재는 제외됐고 모델 호출은 0회였다. 이를 전체 제작 100배 단축이나 원화 품질 개선으로 계산하지 않는다. 원본 시험 자료는 작품별 비공개 기록에 두고 공개물에는 이 범위 요약과 범용 구현만 제공한다.

**다음 측정:** 같은 완료 정의와 품질 기준으로 준비, 모델 대기, 실제 화면 검수, 수정, 조립, Drive 적재와 원본 확인을 기록한다. 활성 시간·대기·유휴를 구분하고 병렬 구간을 중복 합산하지 않는다. 첫 시도 통과율은 실제 생성 시도와 품질 검수 근거가 있을 때만 계산한다. 보존 이미지 수를 모델 호출 성공률로 바꾸지 않는다. 전체 재조립은 필요한 체크포인트에서 수행하고 이미 확인된 원인을 먼저 입력에 반영한다. ## 패키징이 긴 처리 뒤에 필수 파일 누락으로 멈춘다

**감사 관찰:** 여러 조각을 처리한 뒤 폰트 고지 누락이 드러난 과거 패키징 실패가 있었다. 당시 작품별 도구의 선행 검사는 보완됐지만 그 도구를 공개 범용 패키저의 기능으로 설명하지 않는다.

**처리:** 긴 렌더/표식/ZIP 작업 전에 입력 이미지와 manifest, 고지 JSON, 실제 폰트와 필요한 라이선스/고지, 저장 공간, 출력 경로를 확인한다. 출력은 새 버전으로 만들고 원본을 보존한다. 파일의 존재 확인과 라이선스의 법적 검토는 별개다.

**현재 구현:** 공개 고지 패키지는 원본 해시/크기, 본문 픽셀 보존, 분할 순서와 ZIP 무결성을 검사한다. mark 도구는 기존 출력/키 보존과 검증 실패를 처리한다. 범용 라이선스 완전성이나 작품 공개 승인을 자동 발급하지 않는다. [고지 패키지](../../src/ai_notice.py) · [mark 도구](../../tools/mark_review.py) · [mark 검사](../../tests/test_mark_review.py)

## Drive에 보이지만 기록 완료나 로컬 삭제를 판단할 수 없다

**커넥터 용량 제한 확인:** 현재 Drive 업로드 경로는 파일 참조 처리에서 104857600바이트(100MiB)를 넘으면 `413: File too large to download`로 실제 업로드 호출 전에 거절할 수 있다. 이것은 Google Drive 전체의 파일 한도로 일반화하지 않는다. 전송 전 바이트 수를 확인하고 한도를 넘는 묶음은 개별 입력 파일이 한도 아래인 완전한 ZIP들로 나눈다. 모든 ZIP에 원본 경로·묶음 위치·바이트 수·SHA-256 복원 장부를 넣고, 각 원격 ZIP의 원본 바이트와 내부 파일 해시를 다시 확인한다. 요약이나 미리보기만 올린 것을 원본 전체 보관으로 처리하지 않는다.

**감사 관찰:** Figma 페이지/호출 한도, 큰 텍스트 반입 규격, Drive 다운로드 실패, file URL의 브라우저 접근 제한이 있었다. 조건이 바뀌지 않은 동일 호출을 반복하는 것은 해결이 아니다. 특정 시점의 부분 반입과 실패를 전체 기록 완료로 확대하지 않는다.

**처리:** 이미지 해시로 중복 바이트를 줄이되 모든 발생 경로를 연결한다. 전송 묶음 크기와 checkpoint·미반입 목록을 먼저 만든다. 현재 기록 저장소인 Drive에서 전체 제작 이미지·텍스트·이력을 연결하고 원본 바이트를 readback해 해시와 ZIP CRC를 대조한다. 이전 Figma 관찰은 과거 장애 이력이며 신규 Figma 반입은 필수가 아니다. 실패 원인에 맞는 허용된 다른 읽기 경로를 사용하거나 미완료로 남긴다. viewport 이미지와 실제 모바일 브라우저 검수도 구분한다.

**완료 기준:** 허용된 전체 제작 이미지·텍스트·거절/수정·검수 이력과 전체 원본·증빙은 작품별 Drive 비공개 폴더에 통합한다. 재개 정보와 실제 적재 범위/복구 조건을 확인하기 전 로컬 원본을 삭제하지 않는다. secret·개인 대화·허락 없는 원문은 전송 대상에서 제외한다. 로컬 테스트는 이 외부 적재를 증명하지 않는다. [장부 양식](templates/archive_ledger.example.json) · [보관 기준](WORKFLOW_DECISIONS.md)

## 워터마크가 복제나 다른 AI 이용을 막아 주지 않는다

**정정:** 보이지 않는 표식은 keyed 출처 대조용 실험적 픽셀 식별이다. 접근 제어, AI에 강제되는 명령, 저작권 인증 또는 서명된 C2PA가 아니다. crop/resize/편집으로 손상될 수 있다.

**처리:** 비공개 키로 새 RGB PNG를 만들고 encode/readback 후 검증한다. 최종 output hash와 asset ID를 비공개 장부에 연결한다. metadata 원문은 복사되지 않으므로 실제 provider 고지와 라이선스 고지를 별도로 유지한다. 픽셀 변경 뒤 downstream manifest/검수도 갱신한다. ## 프로젝트 스킬 설치가 충돌한다

### 제작 에셋 정리 뒤 B/C 픽셀 회귀검사만 폰트 누락으로 실패한다

doctor는 시스템 한글 폰트를 검사하므로 제작 폴더의 고정 fixture 누락과 독립적으로 통과할 수 있다.
선택 시안 크기 재현 검사는 보존된 교육 묶음의 동일 Pretendard 폰트를 명시해 실행한다.
시스템 폰트로 픽셀 기준을 바꾸거나 검사 성공으로 작화 품질을 승인하지 않는다.

### 한 컷에서 확인한 공통 결함이 다음 컷에서도 반복된다

`sequence_defects.json`은 현재 원고 해시에 묶인 결함 목록이다. `open`은 영향 컷 생성을 막는다.
`validation`은 `validation_cut`, `failed_prompt_sha256`, 바뀐 `validation_prompt_sha256`에
묶인 한 컷만 허용한다. `resolved`는 `resolution.image`(job 내부 상대경로), 이미지 SHA-256,
실제 `observation`, 영향 컷 전체의 `prompt_sha256` 맵이 필요하다. prompt가 바뀌면 다시 stale이다.
전부 반입된 작업도 열린 결함이 있으면 ready로 진행하지 않는다. 기록의 무결성은 관찰 내용의 진실성을 대신하지 않는다.

**처리:** 먼저 `python tools/install_workflow_skills.py --check`로 canonical 스킬 두 개와 repo-local 대상의 상태를 읽는다. 설치가 필요하면 같은 도구의 `--install`을 사용한다. 기존 대상이 다르면 충돌 내용을 확인하고 유지하며 자동 삭제·덮어쓰기로 해결하지 않는다. 설치하지 않아도 canonical 문서를 직접 읽을 수 있다.

**현재 구현:** 고정 파일 전체를 사전 검사한 뒤 누락된 파일만 복사하고, 동일 바이트는 no-op, 충돌·경로 이탈·링크 대상은 거절한다. 글로벌 스킬 설치나 이미지 생성 환경 설치가 아니다. [설치 도구](../../tools/install_workflow_skills.py) · [canonical 복구 스킬](skills/toon-recover/SKILL.md)

## 검증 결과를 어디까지 믿을 수 있는가

### 생성된 정확한 개수와 최종 식자 가림

긴 생성 지시에 정확한 개수를 반복해도 실제 그림의 행·열이 줄어들 수 있다. 원고의 개수가
사건 단서라면 프롬프트의 숫자를 결과 검증으로 쓰지 않는다. 허용된 계수 합성 공정에서는
표식 없는 AI 바탕과 별도 좌표/상태 층을 보존하고, 개수·중복·경계·겹침을 검사한다.
`controlled_lights`의 선택적 `symbol=river`는 파란 강 표식을 그리며 기존 붉은 압력등은 유지한다.
회귀검사는 `tests/test_artwork_balloon.py`에 있다. 합성 직후뿐 아니라 **최종 식자 화면**도 본다.
효과음이 첫 줄의 표식을 덮으면 해당 효과음을 별도 여백으로 옮긴 뒤 다시 조립·검수한다.

수정 재조립 때 이전 `art_anchor`·`protected_art_boxes`를 현재 배치에 남겨 두면 여백으로 옮긴
말풍선도 옛 그림 좌표를 따라갈 수 있다. 새 배치 전 이전 앵커를 제거하고 현재 이미지에서
다시 정한다. 둘째 말풍선의 꼬리도 첫 말풍선의 기준점이 아니라 자기 몸체 가까이에서 검사한다.

새 변경은 격리 export에서 다시 검사하고 skip의 이유·영향을 남긴다. 실제 원화 생성, 원화/식자 전수 관찰, Drive 원본 readback, 사람 승인과 전체 제작 단축률은 위 코드/CI 기록으로 완료되지 않는다. [공개 경계 검사](../../tools/public_release.py) · [경계 테스트](../../tests/test_public_release.py) · [릴리즈 절차](RELEASING.md)
