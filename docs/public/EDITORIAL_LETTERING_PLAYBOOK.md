# 세로 웹툰의 컷 호흡과 말풍선 제작 기준

원고의 사건·대사는 유지하고, 장면의 역할에 따라 크기·간격·모양·효과·식자를 함께 설계한다. 특정 회차에서 승인된 배치는 판단 사례이며 다른 원화에 그대로 적용할 좌표 템플릿이 아니다. 이 절차는 제작 중 얻은 편집 기준이며 독자 실험으로 입증된 공식이 아니다.

## 새 세션의 시작 순서

1. 현재 작품 지침, 원고, 캐릭터, 최신 전달본·승인 범위·열린 결함을 확인한다. 오래된 후보와 최신 승인본을 구분한다.
2. 회차를 도입→곤경 인지→판단→실행→결과 확인→반응으로 나누고, 각 컷이 전달할 정보 하나를 적는다. 원고에 없는 사건을 편집으로 보충하지 않는다.
3. 원화 생성 전에 필요한 가로/세로 비율, 인물 위치, 시선, 핵심 접점, 대사 후보 공간을 텍스트로 정한다. 획일적인 가로 원화를 만든 뒤 세로로 늘이지 않는다.
4. 소수 연결 컷을 생성·관찰한다. 원화에 없는 동작이나 가려진 단서는 재생성이 필요할 수 있다. 장면 확대나 효과선으로 결함을 덮지 않는다.
5. 실제 원화에서 보호 영역과 빈 공간을 지정한 후 풍선 몸체와 꼬리를 작성한다. 현재 원고·원화 해시에 결합하여 조립한다.
6. 원화·개별 식자·연속 세로 조립·작은 화면을 직접 보고 수정한다. 새 배치에는 과거 검수를 복사하지 않는다.

## 컷 크기·간격·모양의 선택

| 장면 기능 | 우선 검토할 배치 | 직접 확인할 것 |
|---|---|---|
| 장소와 위험 경로 | 넓은 전경 | 구조 대상·장애물·도움의 접근 방향이 함께 보이는가 |
| 시선·결심·접점 | 작은 삽입, 좁은 폭 | 축소해도 눈·손발·물건의 관계가 읽히는가 |
| 빠른 연속 행동 | 짧은 간격, 필요할 때 사선 | 전후 이동 방향과 접촉 순서가 유지되는가 |
| 주된 성공·충격 | 큰 컷, 전폭 또는 긴 세로 | 크기가 커지는 이유가 사건의 보상인가 |
| 안도·감사·장소 전환 | 넓어진 간격, 열린 프레임 | 행동 결과를 이해하고 반응을 읽을 시간이 있는가 |
| 끝의 일상 | 힘을 뺀 프레임, 여백 | 위기 해소와 감정적 마무리가 실제로 보이는가 |

폭·높이·간격을 매 컷 번갈아 바꾸는 규칙을 만들지 않는다. 같은 장면의 빠른 연결에는 유사한 구도를 유지할 수 있다. 큰 여백은 시간의 정지나 전환을 뜻하게 하고 단순 빈 공간 채우기로 쓰지 않는다. 사선·무테·페이드는 중요한 얼굴과 동작을 자르지 않아야 한다.

## 말풍선 몸체와 읽는 순서

- 신규 일반 대사 기본 글꼴은 **Pretendard Medium(500)**, 명시적 강조(`weight: "bold"`)는 **Bold(700)**다. 보통 웹툰 대사에 사용할 읽기 좋은 제작 기준으로 채택하며, 검증되지 않은 업계 평균 수치라고 부르지 않는다. 보통 대사를 합성 외곽선으로 굵게 만들지 않는다. 효과음의 별도 halo는 배경 대비용이다.
- 새 대사·효과음·제목·고지에는 검토된 오픈 라이선스 폰트만 쓴다. 공통 `src/font_policy.py`가 환경변수·CLI·개별 `font_path`의 실제 파일 해시와 OFL 전문을 확인한다. 맑은 고딕 등 시스템 폰트로 자동 대체하지 않는다. 공식 출처와 파일은 [폰트 자산 안내](FONTS.md)를 따른다.
- 기존 완성본은 보존한다. 신규 식자는 선택한 실제 Medium/Bold로 몸체를 다시 측정하고 줄바꿈·꼬리·모바일 폭을 검수한다. 글꼴 변경을 이유로 임의 축소하지 않는다. 전달 ZIP에는 `font_licenses.json`과 `licenses/Pretendard-OFL.txt`를 포함한다.
- 최종 화면에서 실제 글꼴·크기·행간·타원 곡면 여백을 측정한다. B/C는 명시적으로 선택한다. 보통 대사, 외침, 짧은 호흡의 크기 차이는 장면의 감정에 맞춘다. 승인된 다른 컷의 선택을 자동 승계하지 않는다.
- 장면 밖 여백과 원화 안 빈 배경을 함께 쓴다. 모든 대사를 동일한 상단 띠에 두거나 모든 풍선을 원화 위로 밀어 넣지 않는다.
- 먼저 독자가 읽어야 할 대사를 위쪽에 놓고, 화자의 얼굴→꼬리→다음 행동의 흐름을 본다. 꼬리가 다른 사람을 가리키거나 여러 꼬리가 교차하지 않게 한다.
- 얼굴·눈·입·손·발·구조 접점·단서가 있는 물건을 보호한다. 몸체 충돌 검사만으로 꼬리·실제 글자·효과음의 가림까지 통과시키지 않는다.
- 공간이 부족하면 몸체 위치, 줄바꿈, 컷 여백, 원화 배치를 고친다. 글자를 계속 줄여 끼워 넣거나 대사를 임의로 고쳐 맞추지 않는다.
- 장면 위 배치는 `art_anchor`, 보호 영역은 `protected_art_boxes` 등 현재 도구의 계약을 따른다. 작품별 별도 렌더러에서는 실제 좌표와 변환 관계를 기록한다. 기록 방식만 같다고 동일한 구현이라고 부르지 않는다.

계산은 [말풍선 실측](../../src/balloon_sizing.py), 식자는 [편집 식자](../../src/editorial_lettering.py), 현재 원고·원화와 조립 결합은 [layout job](../../tools/build_layout_job.py)을 확인한다. 작품별 어댑터를 공용 기본값으로 복사하거나 검수 해시를 직접 고쳐 통과시키지 않는다.

## 효과와 검수

속도선은 움직이는 방향을 돕고, 방사선은 강조 대상을 향하게 한다. 효과음의 크기·기울기·위치는 행동의 강약을 표현한다. 얼굴·접점·다음 대사를 가리거나 효과음이 행동보다 먼저 읽히면 수정한다. 모든 컷에 효과를 넣을 필요는 없다.

각 컷에 다음을 기록한다: 장면 목적, 원화 비율, 화면 크기·정렬·간격·프레임의 이유, 대사 순서, 풍선 유형·실측 크기·줄바꿈·몸체·꼬리, 보호 영역, 효과 위치, 전후 상태, 관찰 근거. 실제 검수는 구도·연기·연속성·호흡·조명·식자·원고 충실도 일곱 항목으로 한다.

완성 세로 조립과 작은 화면에서 모두 읽는다. 여러 모바일 폭으로 렌더한 정지 화면은 유용하지만 실제 기기 스크롤 검증과 구분한다. 좌표·해시·ID 검사는 무결성 근거이며 연출 품질의 자동 승인 근거가 아니다.

## 최종 QA의 회차 간 그림체 허용 범위

마지막 실제 화면 검수에서 인접 회차와 초·중·후반을 비교한다. 공개 연재 사례는 같은 작가·작품의 인접 회차와 시차가 있는 회차를 고르고, 표정·거리·조명이 비슷한 장면의 선·비례·색·묘사 밀도를 비교한다. 사례의 작품명, 회차, 공개 링크, 관찰 근거를 기록한다. 실제 작가의 변화 사례는 정성적 비교 기준이며 업계 평균 수치로 환산하지 않는다. 공개 사례는 열람과 관찰에 사용한다.

- **허용** — 표정 과장, 원근, 시간대·날씨에 따른 색 변화, 배경이나 털 묘사의 밀도 차이, 같은 인물로 읽히는 점진적 변화.
- **확대 확인** — 가까운 컷에서 화풍이 갑자기 달라 보이면 앞뒤 컷과 비슷한 거리·조명의 장면을 원해상도로 비교한다. 인물의 얼굴·실루엣·고유 무늬와 주변 인물·소품에 대한 상대 크기가 이어지는지 본다.
- **수정 필요** — 각도나 연출로 설명하기 어려운 인물 식별 변화, 같은 장면에서 반복되는 상대 체격 변화, 회차 경계에서 이어지는 선·채색 방식의 급변. 해당 컷과 비교 컷, 판정 근거, 수정 후 다시 볼 범위를 기록한다.

회차별 전 컷 비교표와 후보 컷 확대 검수 결과를 최신 조립본의 파일 해시에 연결한다. 애매한 소폭 차이는 관찰로 남기고, 독자가 인물이나 사건을 다르게 읽게 되는 변화부터 수정한다. 이 항목은 기존 실제 화면 7항목에 더하는 최종 수동 확인이다.

판단 근거로는 연재 중 세부 묘사와 화풍이 변화할 수 있다는 [Clip Studio Paint의 작화 가이드](https://www.clipstudio.net/en/comics-manga/developing-style/)와, 연재 중 변화가 작가에게 작품을 보류할 만큼 커질 수 있었던 [Amerciix의 Fireborn 연재 노트](https://www.webtoons.com/en/canvas/fireborn/list?title_no=1100637)를 참고한다.

## 전달과 다른 세션의 재사용

독자용 화면은 공통 AI 제작·권리 고지→작품 로고→회차 제목→본문 순서로 만든다. 내부 작업 ID·제작일·검토 상태는 별도 장부에 두고, 사용자 지시에 따라 독자 화면에서는 제외한다. 끝과 다음 회차 안내는 작품별 요구를 따른다.

작품별 비공개 사례 묶음에는 최신 승인본의 해시, 실제 편집 계획·구현·관찰 기록, 사례별 판단 이유, 복구 목록을 연결한다. 새 세션은 사례를 읽고 현재 장면에 맞게 계획한다. 사례의 인물·대사·사건을 다른 작품의 원고로 가져오지 않는다. 관찰용 이미지와 생성 모델 입력 권한은 별개다. 저장과 원본 바이트 검증은 [제작 운영](PRODUCTION_RUNBOOK.md)을 따른다.
