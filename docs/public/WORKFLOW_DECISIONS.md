# 제작 공정의 결정과 적용 범위

이 문서는 제작 중 확인한 실패와 정책 정정을 재사용 가능한 규칙으로 정리한 독립 노트다. 원고·캐릭터·대사·작품별 프롬프트·개인 대화·비공개 저장소 식별자는 포함하지 않는다. 과거 규칙을 전부 현재 작업에 중첩해서 적용하지 않고, 작업의 현재 입력 모드와 검토 기록을 따른다.

실행 순서는 [ComfyUI 인계](COMFYUI_HANDOFF.md)와 [제작 운영](PRODUCTION_RUNBOOK.md), 원고·구도의 판단은 [작가 공정](AUTHORING_WORKFLOW.md), 증상별 복구는 [트러블슈팅](TROUBLESHOOTING.md)을 읽는다. 이 문서의 **정책 결정**, 코드로 확인 가능한 **구현**, 실제 그림이나 장치에서 확인해야 하는 **미검증 항목**을 구분한다.

## 1. 재발 방지를 생산량보다 우선한다

**결정:** 한 번 확인한 원인은 다음 컷의 실제 입력과 공정에 바로 반영한다. 수정 기록을 쌓는 것만으로 결함을 닫지 않는다. 공통 결함이 해결되기 전 해당 시퀀스의 확장 제작을 멈춘다. 정확성·허용 범위·보안을 낮춰 속도를 맞추지 않는다.

**구현:** 장면 상태의 원고 해시 결합, 현재 수정 지시의 단일화, 실패 분류에 따른 재계획 검사와 `next`의 차단 경로가 있다. 계산과 기록의 일관성을 검사하는 장치이며 새 전략의 효과를 판정하지는 않는다. [제어 코드](../../src/production_control.py) · [다음 단계](../../src/operations.py) · [회귀검사](../../tests/test_production_control.py) · [재계획 경로 검사](../../tests/test_operations.py)

**수동 경계:** 공개 범용 소스의 함수가 거절 분류·attempt·재계획 기록을 스스로 작성하는 것은 아니다. 작품별 비공개 wrapper에서 수행하던 기록·차단 연결을 공개 CLI의 자동 기능으로 설명하지 않는다. 범용 경로에서는 실제 관찰에 따라 기록을 작성하고 `next`의 검사를 적용한다. 기록 구조와 해시 결합은 [제작 운영](PRODUCTION_RUNBOOK.md)을 따른다.

**한계:** 같은 분류의 연속 두 실패는 최후의 차단 조건이다. 이미 원인을 아는 실패를 한 번 더 허용하는 제작 목표가 아니다. 사람이 결함을 관찰하면 자동 차단 전에도 즉시 고친다.

## 2. 원고와 장면 상태를 최초 입력에서 연결한다

**결정:** 사건·장면 ID·순서는 원고를 기준으로 고정한다. 공통 장소와 시각적 불변 조건, 컷별 구도·소품 상태·보호 대상을 간단히 작성하고 실제 최초 생성 지시에 포함한다. 직전·다음 컷과 회차 경계도 비교한다.

**구현:** `compile_context`는 원고 바이트 SHA-256, 장면 ID의 전체 범위와 순서, `source_action`의 원고 일치, 필수 상태 필드를 검사한다. `generation_context.json`을 쓰는 작업은 현재 workflow evidence의 동일 경로·해시에 연결되어야 한다. 회차 지시는 로컬에서 묶어 준비할 수 있다. [장면 상태](../../src/production_control.py) · [일괄 준비](../../tools/compile_production_batch.py) · [검사](../../tests/test_production_control.py)

**한계:** 필드가 비어 있지 않다는 사실은 상태 내용의 정확성을 증명하지 않는다. 컴파일러가 이야기나 공간 관계를 새로 판단하지 않는다. 잘못 작성된 상태표도 원고·실제 그림과 대조해야 한다.

## 3. 과거 수정은 이력에, 현재 수정은 실행 입력 하나에 둔다

**결정:** 이전 지시와 반대되는 새 지시를 같은 prompt 뒤에 계속 덧붙이지 않는다. 원래 브리프와 최신 수정 하나로 현재 입력을 만들고 이전 시도·거절 이유는 별도 이력에 보존한다.

**구현:** `replace_correction`과 batch 준비는 현재 수정 블록을 하나로 정리한다. 재계획 해제에는 실제 변경된 prompt 해시, 재계획 기록의 해시, 변경 전략이 필요하다. [구현](../../src/production_control.py) · [batch 도구](../../tools/compile_production_batch.py) · [검사](../../tests/test_production_control.py)

**한계:** 해시 결합과 전략 문자열은 수정이 있었다는 기록이다. 결과가 좋아졌다는 증거는 새 원화와 식자 검수에서 얻는다.

## 4. 생성 입력 모드와 참조 허용은 작업·도구별로 기록한다

**결정:** 기본 `text_only`는 자체·타인 이미지를 모두 생성 입력에서 제외한다. 별도로 승인된 자체 첫 회차 원화 참조 예외는 지정 파일·해시·권한·개수·도구와 승인된 스타일 비교 기준에 결합한다. 비교 검수에 사용한 새 결과를 후속 생성 참조로 자동 추가하지 않는다.

**구현:** text-only 작업은 이미지 필드를 거절한다. 기존 `authorized_own_episode1_reference` 경로는 지정 카탈로그와 컷당 원화 한 장의 실제 사용 선언을 검사한다. 과거 작업의 mode와 실제 입력 이력을 소급 변경하지 않는다. [text-only 계약](../../src/generation_policy.py) · [자체 원화 계약](../../src/owned_episode_reference.py) · [검사](../../tests/test_factory.py) · [자체 원화 검사](../../tests/test_owned_episode_reference.py)

**정정:** 과거 imagegen의 자체 원화 참조 허용은 ComfyUI의 새 모델·노드·수신자에 대한 입력 허용이 아니다. 현재 factory의 ComfyUI 반입은 검토된 core class를 사용하는 text-only graph로 제한한다. 임의 API graph를 실행하는 native runner와 factory의 제작 정책을 구분한다. [Comfy 반입](../../src/factory.py) · [반입 검사](../../tests/test_comfy_factory.py)

**미검증:** 텍스트 반복이나 원화 한 장 참조가 완전히 같은 그림체·인물·장소를 보장하지 않는다. 스타일 일치와 참조 내용의 유입 여부는 실제 비교해야 한다.

## 5. 구도 밑작업은 간단히, 실제 수행한 단계만 기록한다

**결정:** 원고에서 인물 위치·시선·핵심 소품·컷 배치·대사 공간을 선이나 텍스트로 정리한다. 상세 AI 밑그림을 반복 생성하는 공정을 필수로 삼지 않는다. 구도 의도는 텍스트로 완성 원화에 전달하고 결과를 비교한다.

**정정:** 제작 기록이 필요하다는 요구를 추가 이미지 생성 횟수로 해석하지 않는다. 수행하지 않은 스케치·펜선·채색을 있었다고 만들지 않는다. 도식·과거 러프를 생성 입력에 넣는 것은 별도 허용 사항이다.

**구현 범위:** 상태 컴파일과 batch 준비는 텍스트를 다룬다. 실제 러프나 원화를 자동 생성하지 않는다. [상태 제어](../../src/production_control.py) · [batch 준비](../../tools/compile_production_batch.py)

## 6. 장면 배치는 의미 입력에 따라 계산한다

**결정:** 모든 원화를 같은 폭의 세로 카드로 나열하는 방식에 고정하지 않는다. 원고 순서와 장면 목적을 유지하면서 역할, 현재/회상, 연결·전환·강조, 정지 지점을 편집자가 지정한다. 첫 회차와의 비교 요청은 단순 크기 복사가 아니라 구도·호흡·시선 흐름의 실제 비교 질문으로 바꾼다.

**구현:** `layout_policy`는 명시된 의미 태그로 폭·정렬·전환 여백을 계산하고 원본 비율과 전체 장면 범위를 보존한다. 선택적인 모바일 높이 예산도 지원한다. 누락·재정렬·잘못된 태그는 거절한다. [정책](../../src/layout_policy.py) · [합성](../../src/layout_composer.py) · [검사](../../tests/test_layout_policy.py)

**한계:** 역할·시간·강조를 이미지에서 자동 추론하지 않는다. 기본 수치는 프로젝트 편집 선택이며 보편적인 작법 공식이나 독자 반응 실험 결과가 아니다. 기하 검사는 연출 품질 검수가 아니다.

## 7. B/C 실측과 말풍선 배치를 별도로 검수한다

**결정:** B/C는 명시적으로 선택하고 실제 폰트의 글자 폭·높이·행간과 곡면 여백으로 몸체를 계산한다. 공간 부족을 글자 자동 축소로 숨기지 않는다. B 기본/C 강조 같은 연출 규칙은 별도 채택할 선택이며 모든 장면의 고정 규칙으로 추정하지 않는다.

**구현:** B/C 측정과 editorial renderer는 지정 몸체의 실측 일치를 검사한다. 잘못된 크기는 오류로 처리한다. [실측](../../src/balloon_sizing.py) · [식자](../../src/editorial_lettering.py) · [휴대 가능한 검사](../../tests/test_balloon_sizing_portable.py)

**정정:** 모든 대사를 장면 밖 띠로 옮기는 것은 일반 해결책이 아니다. 장면 위 빈 공간에는 `art_anchor`, 얼굴·손·행동·단서에는 `protected_art_boxes`를 작성한다. 글자와 몸체 크기를 유지한 채 원화 위치에 따라 배치한다. [좌표 변환](../../src/layout_composer.py) · [장면 중첩 검사](../../tests/test_artwork_balloon.py)

**미검증:** 좌표가 맞아도 화자·꼬리·표정·독서 순서는 틀릴 수 있다. 이전 회차의 B/C 집합과 SFX 좌표를 현재 장면 확인 없이 복사하지 않는다. 과거 말풍선 불만은 전체 수정·재관찰 증거가 나올 때까지 해결로 집계하지 않는다.

## 8. 후보를 정식 검수 상태와 연결한다

**결정:** 별도 후보 파일이 있다는 사실을 회차 완료로 세지 않는다. 현재 raw 원화, 원고, 배치 입력, 조립 manifest와 실제 관찰 검수를 한 작업의 상태에 연결한다. 수정 전 후보·거절 원화·사용 이력은 보존한다.

**구현:** factory는 반입 버전을 보존하고 변경된 원화를 감지한다. `build_layout_job`은 현재 raw와 동일한 이미지, 원고의 대사·description·장면 순서를 요구하며 배치 스냅샷과 출력 해시를 결합한다. 출력 변경 뒤 기존 관찰 보고서를 그대로 재사용하지 않는다. [factory](../../src/factory.py) · [배치 결합 도구](../../tools/build_layout_job.py) · [생명주기 검사](../../tests/test_factory.py) · [검수 상태 검사](../../tests/test_operations.py)

**완료 기준:** 원화·식자·세로 조립/모바일을 실제 보고 구도·연기·연속성·호흡·조명·식자·원고 충실도의 7항목을 기록한다. 보지 않은 항목은 `not_reviewed`다. `ready`와 사람의 작품 승인·공개 승인은 각각의 상태다.

## 9. 공정의 권리 검토와 매회 생성 승인을 혼동하지 않는다

**결정:** 실제 입력 권한·라이선스·외부 처리 범위와 근거 해시를 연결한 검토 공정을 명시적으로 채택할 수 있다. 이 경로에서 법률 API/Jev는 중요한 공정 변경·권리 제보·구체적 의심을 검토하는 도구로 사용한다. 채택하지 않은 호환 작업은 기존 사전/최종 게이트를 유지한다.

**구현:** `adopt-workflow`는 입력/근거 변경과 권리 보류를 차단하며 과거 미검사를 통과로 바꾸지 않는다. 실제 prompt·입력 사용 이력, 산출물 무결성과 관찰 검수는 계속 필요하다. [공정 정책](../../src/workflow_policy.py) · [검사](../../tests/test_workflow_policy.py) · [법률 QA 범위](LEGAL_QA.md)

**한계:** 운영자 선언, 모델 확률, 해시 또는 소프트웨어 라이선스는 작품의 무침해 인증이 아니다. 제공자의 공개 범위 밖 사전학습 경위까지 검증했다고 주장하지 않는다. 외부 QA에 필요한 최소 허용 자료만 전송한다.

## 10. 고지·워터마크·원본 증빙의 역할을 구분한다

**결정:** 실제 AI 활용과 검토 범위를 상단 고지에 밝히고 최종 파일에 제작·수정·검수 이력을 연결한다. 없는 제보 채널을 운영 중으로 표시하지 않는다. 식별 워터마크는 출처 대조를 보조한다.

**구현:** 고지 패키지는 기존 본문 픽셀과 manifest를 대조하고 새 검토본으로 만든다. mark 도구는 새 RGB PNG에 keyed 식별 표식을 넣고 encode/readback 뒤 확인하며 기존 파일을 덮지 않는다. 키는 비공개로 분리한다. [고지](../../src/ai_notice.py) · [패키지](../../tools/package_webtoon.py) · [표식](../../tools/mark_review.py) · [표식 검사](../../tests/test_mark_review.py)

**한계:** 워터마크는 복제·AI 학습·재생성을 기술적으로 막지 않으며 서명된 C2PA나 권리 인증이 아니다. 픽셀 변경 뒤 최종 해시와 downstream manifest를 갱신하고 새 전달본을 다시 본다.

## 11. 기록 저장과 로컬 정리는 readback 뒤 수행한다

**결정:** 2026-11-01 사용자 변경 지시에 따라 허용된 모든 제작 이미지·텍스트와 수정/거절/검수 이력, 전체 원본·증빙을 작품별 Google Drive 비공개 전용 폴더 하나에 통합한다. 이전의 Figma 병행 의무는 해제하며 기존 기록은 보존한다. 로컬 최종 보유 대상은 릴리즈 가능한 전달본이다. 진행 중 파일은 적재 검증이 끝날 때까지 임시 보유한다.

**검증 기준:** 동일 바이트의 중복 저장은 줄이되 모든 발생 경로와 버전을 연결한다. 원본/전송본 해시, Drive 파일/폴더 ID, 변환 관계, 미반입 이유와 재개 방법을 남긴다. 파일 목록이나 업로드 성공 응답을 원본 바이트 readback으로 바꾸어 적지 않는다. Drive의 실제 기록과 복구 조건이 확인되기 전 로컬 원본을 삭제하지 않는다. [보관 장부 양식](templates/archive_ledger.example.json)

**한계:** Drive 적재는 이 저장소의 로컬 테스트로 완료되지 않는다. 인증정보·개인 대화·권한 없는 원문은 전체 자료 적재 요구의 예외로 제외한다. 공유 권한을 자동 확대하지 않는다.

## 12. 속도는 품질을 충족한 전체 완료 시간으로 측정한다

**결정:** 큰 폭의 시간 단축은 목표이며 실측 없이 달성으로 보고하지 않는다. 준비, 모델 대기, 관찰 검수, 수정, 조립, 기록 적재와 원본 확인을 나누어 측정한다. 생성 호출 수·후보 파일 수를 완성 장면 수로 바꾸지 않는다.

**확인된 범위:** 상태 컴파일·수정 정규화·batch 준비는 반복 입력과 충돌을 줄이는 구현이다. 로컬 텍스트 처리 시험은 이미지 품질이나 전체 제작 단축률의 증거가 아니다. [제어 코드](../../src/production_control.py) · [batch 도구](../../tools/compile_production_batch.py) · [검사](../../tests/test_production_control.py)

**미검증:** 이전에 제시된 100배 단축 목표와 연속 작업시간의 전체 분해는 측정 완료 상태가 아니다. ComfyUI 설치나 CUDA probe도 캐릭터·공간·식자 문제 해결을 보장하지 않는다. RTX 5060은 예정 대상이며 실제 GPU 생성은 별도 기록해야 한다.

## 13. 재사용 지식은 남기고 제작 원본은 공개 소스와 분리한다

**결정:** 다른 에이전트가 다시 겪을 실패는 증상·원인·수정·재발 방지·검증 범위로 정리한다. 공개 인계에는 범용 코드·절차·예제·스킬만 담고 작품 에셋과 원문 대화·제작 로그를 복사하지 않는다. private repository에도 같은 source-only 경계를 적용한다.

**구현:** 명시적 allowlist로 격리 export하고 공개 트리·ZIP·의존성과 staged 내용을 검사한다. 새로운 파일과 테스트를 추가하면 새 export를 검증한다. [export 도구](../../tools/public_release.py) · [경계 검사](../../tests/test_public_release.py) · [릴리즈 절차](RELEASING.md)

공개 스킬의 canonical 문서는 `docs/public/skills/`에 둔다. 선택적 [설치 도구](../../tools/install_workflow_skills.py)는 고정된 시작·제작·복구 스킬 세 개만 repo-local `.agents/skills/`로 복사한다. 기본 `--check`는 읽기 전용이고 `--install`은 명시적 설치다. 동일 내용은 유지하고 충돌 파일은 덮지 않는다. 전역 설정·네트워크·모델 설치와 구분한다. [복구 스킬](skills/toon-recover/SKILL.md)

**한계:** 이전 스냅샷의 테스트·원격 바이트 대조·CI 성공은 새 변경의 검증 결과가 아니다. 실행 기록과 완료 보고는 해당 commit와 실제 검사 범위에 결합한다.
