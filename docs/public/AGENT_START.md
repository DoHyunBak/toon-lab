# 다음 에이전트의 시작 규칙

처음에는 [README](../../README.md)와 [라이선스 범위](LICENSE_SCOPE.md)를 읽는다. 내장 또는 연결된 이미지 생성 도구가 있으면 [에이전트 이미지 제작 절차](AGENT_IMAGE_WORKFLOW.md)를 사용한다. 사용자가 로컬 GPU 경로를 선택하면 [ComfyUI 인계](COMFYUI_HANDOFF.md)를 따른다.

## 최우선: 확인한 실수를 다시 만들지 않는다

속도·생산량·후보 수보다 재발 방지를 앞에 둔다. 정확성, 허용 범위, 보안을 낮춰 속도를 맞추지 않는다.

- 확인된 실패 원인은 바로 다음 실제 입력과 공정에 반영한다. 기록만 남긴 채 같은 설정으로 반복 생성하지 않는다.
- 결함은 증상 → 확인된 원인/남은 가설 → 수정 → 재발 방지 장치 → 검증 근거로 닫는다.
- 공통 결함을 발견하면 해당 시퀀스의 확장을 멈추고 작은 시험으로 고친다. 독립 작업은 계속할 수 있다.
- 계산·상태·해시 오류는 코드와 적절한 회귀검사로 막는다. 작화·연기·배치는 실제 이미지를 보고 비교한다. 테스트 통과를 시각 품질 통과로 확대하지 않는다.
- 과거 컷의 좌표, B/C 선택, 장소, 소품 상태, 프롬프트를 현재 장면 확인 없이 재사용하지 않는다.

## 착수 시 확인

1. `git status`와 저장소 루트, 현재 변경사항을 확인한다. 기존 변경을 덮거나 강제 reset하지 않는다.
2. 사용자가 정한 범위, 원고·장면 ID·순서·캐릭터 설정과 성공 조건을 확인한다. 아이디어 기반 창작이 요청 범위면 짧은 원고를 작성한다. 기술 시험에는 범용 예제를 쓴다.
3. 입력 자료의 출처, 필요한 복제/생성/전송 범위와 허용 근거를 확인한다. 공개 접근, GPT 생성 설명, 이전 이용만으로 모든 권리를 추정하지 않는다.
4. 실제 현재 상태, 그래프/모델/산출물 해시, 최근 실패, 열린 결함, 승인 범위와 다음 한 단계를 읽는다. 상태를 알 수 없으면 작은 확인부터 한다.
5. GPU·모델·참조가 없는 단계는 준비 완료와 실제 실행 미완료를 구분한다. 이미 받은 같은 범위의 실행 승인을 반복해서 묻지 않는다.

## 작업 순서

계획 → 간단한 선/텍스트 구도 → 선택한 이미지 도구로 원화 생성 → 식자·장면 배치 → 원화/모바일 실제 검수·수정 → 고지·증빙 순서로 진행한다. 기본 전달 위치는 로컬이다. 상세 AI 밑그림을 반복 생성하는 공정을 필수로 추가하지 않는다.

생성 입력은 작업에 선언된 모드를 따른다. `text_only`에는 자체/타인 이미지를 모두 넣지 않는다. 자체 원화 참조가 별도 허용된 경우에는 해당 파일·해시·용도·개수·수신자 범위만 사용한다. 관찰용 출력이나 QA 비교 자료를 생성 참조로 자동 승격하지 않는다. 기존 이력의 mode나 실제 사용 기록을 고쳐 새 기준을 소급 통과시키지 않는다.

ComfyUI 설정과 실제 실행은 [COMFYUI_HANDOFF](COMFYUI_HANDOFF.md)를 따른다. 기존 SD1.5/SDXL 어댑터와 native API graph runner의 기능을 구분한다. API graph를 실행했다고 기존 작화가 유지됐다고 판단하지 않는다. 먼저 한 컷을 실제 생성·비교한 뒤 소수 연결 컷과 회차로 확대한다.

## 구현과 검수

- 요청에 필요한 최소 파일만 수정한다. 동작 중인 주변 코드를 취향으로 리팩터링하거나 원고 내용을 바꾸지 않는다.
- 확정 계산·기하·해시·상태 검사는 결정적인 코드로 처리한다. 의미 판단 도구의 점수를 실제 관찰이나 권리 근거 대신 쓰지 않는다.
- 말풍선은 장면 위에 겹칠 수 있다. 장면을 보고 빈 공간과 보호 영역을 지정하며 얼굴·손·단서를 가리지 않는지 직접 확인한다. 글자 실측을 유지한다.
- 원화, 식자 결과, 세로 조립과 모바일 정지 화면을 직접 검수한다. 구도·연기·연속성·호흡·조명·식자·원고 충실도에 관찰 근거를 남긴다. 보지 않은 항목은 `not_reviewed`로 둔다.
- 새 버전은 이전 후보와 거절 이력을 보존한다. 이미지·조립본이 바뀌면 해당 해시에 연결된 검수를 다시 확인한다.
- 실제 실행한 검사만 성공으로 보고한다. source/offline/mock/server preflight/GPU generation/visual review/human approval을 구분한다.

## 보안과 자료 경계

API key, `.env`, 인증서, 계정정보, 개인 대화 캡처, 권한 없는 원문, 서명 URL을 Git·채팅·공개 로그에 넣지 않는다. ComfyUI/custom node를 localhost에서 실행해도 그래프 안의 API 노드가 외부로 전송할 수 있으므로 실제 경로를 확인한다. 원격 서버, 모델 다운로드, custom node 설치, 학습과 새 외부 서비스는 현재 허용 범위를 확인하고 진행한다.

Git에는 검토된 재사용 소스·범용 예제·운영 문서만 둔다. 새 공개 파일은 명시적 allowlist와 격리 export를 거친다. 작품 텍스트가 들어 있는 코드도 작품 자료다. private repository라는 이유로 에셋이나 secret을 추가하지 않는다. 공개 트리/ZIP/staged 내용을 확인하고 [릴리즈 절차](RELEASING.md)를 따른다.

## 보관과 재개

제작 이미지·텍스트·수정 이력과 증빙은 기본적으로 `workspace/local/`에 보존한다. 사용자가 별도 백업 대상을 지정한 경우 실제 원본 바이트와 복구 정보를 확인한 뒤 정리한다. 저장소의 공유 범위를 자동 확대하지 않는다.

작업 종료/인계 기록은 현재 단계, 유효한 입력/출력 해시, provider receipt/prompt_id, 열린 결함과 원인, 실제 승인 범위, 다음 한 단계와 복구법을 포함한다. 활동 횟수보다 닫힌 결함, 재발 여부, 실제 완료 결과를 보고한다. 워터마크는 출처 식별 보조이며 복제 방지나 법적 권리 인증이라고 주장하지 않는다.

문서 작성, 기술 ready, 실제 관찰 검수, 최종 작품 승인, 공개/배포 승인은 각각의 상태다. 미확인·미실행·보류를 완료로 바꾸지 않는다.
