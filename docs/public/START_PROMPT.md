# 에이전트 이미지 도구로 한 컷 제작 시작

## 2026-11-03 완성본 PNG 적재 전 압축

신규 완성본의 최종 조립·실제 검수 후 Drive 적재 전에 루트 `compress_png.py`를 실행한다.
[무손실 압축 사용법과 다른 세션용 프롬프트](PNG_COMPRESSION.md)를 따른다.
`python compress_png.py "workspace/delivery/master.png" "workspace/delivery/compressed/001화 - 회차 제목.png"`

원본·기존 출력은 보존한다. 압축 영수증의 스캔라인/비-IDAT 청크 동일성과 전후 SHA-256·크기를
확인하고, 실제 Drive 원본 바이트 readback을 출력 해시·크기와 대조한다. 완성본에는 PNG만,
압축 전 원본·JSON·증빙은 작품별 백업/기록 폴더에 둔다. 용량 감소가 없어 원본을 채택해도 정상이다.
압축 실패 시 적재를 중단한다. 로컬 압축은 작품 승인·원격 검증을 대신하지 않는다.


사용자가 이 저장소를 작업 폴더로 연 에이전트에게 남길 요청 예시다.

```text
이 저장소의 AGENTS.md를 읽고, 네 이미지 생성 도구로 샘플 웹툰 한 컷을 만들어줘.
그림에는 글자를 넣지 말고 Python으로 한글 식자와 세로 PNG 조립을 해줘.
완성 PNG와 실제 생성·검수 기록의 경로를 알려줘.
```

원고가 있으면 원고의 사건·대사·컷 순서를 보존한다. 아이디어 기반 창작을 요청하면
짧은 콘티부터 작성한다. 단순 문서 열람·수정 요청을 생성 실행 지시로 해석하지 않는다.

## 에이전트가 실행할 순서

1. `AGENTS.md`, `README.md`, `docs/public/AGENT_IMAGE_WORKFLOW.md`를 읽는다.
   제작은 `toon-production`, 중단된 작업은 `toon-recover`의 canonical 문서를 따른다.
   스킬 설치와 새 채팅은 실행의 필수 조건이 아니다.
2. 연결된 이미지 도구의 생성·보기·로컬 저장 가능 여부와 Python·Pillow·Pretendard를
   확인한다. 실제 생성이 불가능하면 제약을 설명하고 원고 정리나 오프라인 데모를 진행한다.
3. 기존 job의 `status`와 `next`, 실제 입력·출력 해시와 검수 이력을 확인한다.
   같은 목표의 유효한 완료본이 있으면 재사용하고 중복 생성하지 않는다.
4. 허용된 입력 범위를 확인한 뒤 한 컷을 생성한다. 실제 도구·모델(제공되는 경우)·
   전달한 프롬프트·생성 파일을 기록한다. 상세 러프 반복은 필수가 아니다.
5. 원화를 등록하고 Python으로 한글 식자·말풍선·여백·세로 조립을 처리한다.
   원화와 모바일 폭의 최종 결과를 직접 확인하고 문제를 수정한다.
6. 출력 절대 경로, 실제 수행한 검사와 남은 제약, 다음 단계를 보고한다.
   mock·환경 준비·실제 생성·시각 검수·사람 승인을 각각 구분한다.

원고·생성 이미지·실제 프롬프트·개인 기록·키는 Git에 추가하지 않는다.
커밋·외부 전송·게시·유료 사용은 현재 사용자 지시가 허용한 범위를 따른다.
