# 대화 결정과 재개 방법

이 문서는 현재 대화와 프로젝트 기록에서 재사용할 운영 판단을 독립적으로 정리한
인계 노트다. 대화 원문·개인 채팅·원고·작품 에셋의 사본이 아니며 전체 대화 로그가
들어 있다고 주장하지 않는다. 기록되지 않은 실행·승인·과거 시간을 만들어 채우지 않는다.

## 현재 제작 경로와 경계

- 원화는 에이전트에 연결된 이미지 생성 도구로 만들고 Python으로 식자·조립한다.
- 기존 완료본과 실패·수정·검수 기록은 보존한다. 같은 목표의 유효한 한 컷을 중복 생성하지 않는다.
- 자체 원화 참조는 명시적으로 허용된 파일·해시·개수·도구·수신자 범위에서만 사용한다.
- 한 컷 시험을 본편 제작·새 스토리·공개·유료 사용으로 자동 확대하지 않는다.
- 상세 러프 반복 대신 간단한 구도, 실제 검수와 원인 수정에 시간을 쓴다.

정책은 [공정 결정](WORKFLOW_DECISIONS.md), 증상별 재발 방지는
[트러블슈팅](TROUBLESHOOTING.md), 실제 포괄 범위는 [인계 범위](HANDOFF_COVERAGE.md)를 따른다.
과거 스냅샷의 검사 결과를 현재 변경의 검증 결과로 사용하지 않는다.

## 새 환경에서 읽는 순서

1. root AGENTS/README → `AGENT_START.md`와 현재 git 변경사항.
2. 제작은 `toon-production`, 복구는 `toon-recover`.
3. 실제 작업의 목적·현재 단계·원고/프롬프트/출력 해시·미해결 결함과 생성 기록.
4. 입력 권한·검토·사람 승인의 실제 범위와 다음 한 단계.
5. 연결된 비공개 원본과 저장 위치 접근 여부. 자료가 없으면 샘플과 본편 재개를 구분한다.

기존 경로를 다른 환경에 그대로 적용하지 않는다. 저장소 root와 실제 입력·이미지 도구를
확인한다. 파일이 없다고 다른 회차나 예제의 사건을 현재 본편으로 바꾸지 않는다.
repo 소스와 GitHub commit만으로 비공개 작품 전체가 복구된 것은 아니다.

## 컨텍스트 정리와 상태 보존

사용자는 긴 작업에서 500K 이전 compact 수행을 요청했다. 실제 클라이언트의 토큰
계측과 compact 기능이 있는지 확인한다. 없는 기능을 호출했다거나 모든 환경에서
정확한 토큰 시점에 자동 실행된다고 보장하지 않는다. 길어지기 전에 작업 상태를
짧게 정리하고 클라이언트의 기능을 사용한다.

대화 요약은 다음 네 줄로 작성한다.

```text
목표: 현재 요청과 완료 조건.
결정: 실제로 확정된 입력·권한·작화·공정 제약.
미결: 미검증·실패·승인 대기와 현재 근거.
다음: 바로 실행할 한 단계와 상태/receipt 위치.
```

별도의 실제 작업 상태는 무시되는 `workspace/local/`에 기록한다. 기록 항목은
current job와 cut ID, source/prompt/output SHA-256, 실제 도구와 제공되는 생성 기록, 최근 결함·원인,
현재 전략, 실제 승인 범위, 다음 명령, 적재/readback 상태다. 실제 프로젝트의 양식이
있으면 그 정본을 갱신하고 비슷한 상태 사본을 계속 만들지 않는다.

대화 요약과 파일 기록은 다른 목적이다. compact 자체가 파일 저장·승인·목표 생성·
Git 작업을 수행한 것으로 취급하지 않는다. 재개 후에는 요약만 믿지 말고 기록된
파일/해시와 도구의 실제 결과를 대조한다. secret과 개인 대화는 인계 요약에 넣지 않는다.
