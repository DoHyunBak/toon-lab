# 대화 결정과 재개 방법

이 문서는 현재 대화와 프로젝트 기록에서 재사용할 운영 판단을 독립적으로 정리한
인계 노트다. 대화 원문·개인 채팅·원고·작품 에셋의 사본이 아니며 전체 대화 로그가
들어 있다고 주장하지 않는다. 기록되지 않은 실행·승인·과거 시간을 만들어 채우지 않는다.

## 현재 요청과 경계

- 작업 PC의 예정 GPU는 RTX 5060이다. 실제 장치·VRAM·드라이버·GPU 생성은 수신 PC에서 확인한다.
- ComfyUI를 새 제작 환경으로 사용한다. 소스와 운영 지식을 저장소로 인계하고 에셋은 별도 비공개 경로에 둔다.
- 착수 시험은 설치부터 한 컷 실제 생성까지다. 본편 제작·새 스토리·공개·유료 사용으로 자동 확대하지 않는다.
- 이 대화의 최종 추가 요청은 프로젝트의 재사용 가능한 workflow, troubleshooting과 착수 스킬을 저장소에 함께 담는 것이다.
- 이전 자체 원화 참조 승인은 imagegen 입력 계약에 결합돼 있다. ComfyUI 참조용 새 모델·노드·수신자 허용을 자동 추정하지 않는다.
- 최우선은 같은 실패를 반복하지 않는 것이다. 상세 러프 반복 대신 간단한 구도, 실제 검수와 원인 수정에 시간을 쓴다.

정책의 흐름과 상태는 [공정 결정](WORKFLOW_DECISIONS.md), 증상별 재발 방지는
[트러블슈팅](TROUBLESHOOTING.md), 실제 포괄 범위는 [인계 범위](HANDOFF_COVERAGE.md)를 따른다.

82개 파일이었다. 로컬 격리 검사 247개 중 245개 통과·링크 권한 관련 2개 skip,
GitHub Python 3.11/3.12 CI 성공과 원격 파일 82개의 blob 해시/크기 일치를 확인했다.
이는 해당 commit의 소스/프로토콜/모의 검사 근거이며 RTX 5060 GPU·작화·본편 제작의
검증이 아니다. 이후 commit은 새 CI/manifest를 확인해야 한다.

이전 검사에서 비공개 작품 폰트 경로를 사용하는 테스트가 격리 실행에 실패했다.
원본 회귀검사는 보존하고 공개 묶음에는 별도 synthetic portable 테스트를 넣었다.
출처 식별은 source exporter의 작품 경로 차단과 명시적 목록으로 보호했다.

## 새 PC에서 읽는 순서

1. root AGENTS/README → `AGENT_START.md`와 현재 git 변경사항.
2. 목적에 맞는 스킬: 설정은 `toon-comfy-start`, 본편은 `toon-production`, 복구는 `toon-recover`.
3. 실제 작업 기록의 목적·현재 단계·원고/graph/model/receipt/output 해시·미해결 결함.
4. 정책·QA·사람 승인의 실제 범위와 다음 한 단계.
5. 연결된 비공개 원본과 저장 위치 접근 여부. 자료가 없는 경우 기술 시험과 본편 재개를 구분한다.

기존 경로를 다른 PC에 그대로 적용하지 않는다. 저장소 root와 실제 로컬 입력·서버를
확인한다. 파일이 없다고 다른 회차나 예제의 사건을 현재 본편으로 바꾸지 않는다.
repo 소스와 GitHub commit만으로 비공개 작품 전체가 복구된 것은 아니다.

## 컨텍스트 정리와 상태 보존

사용자는 긴 작업에서 500K 이전 compact 수행을 요청했다. 실제 클라이언트의 토큰
계측과 compact 기능이 있는지 확인한다. 없는 기능을 호출했다거나 모든 환경에서
정확한 토큰 시점에 자동 실행된다고 보장하지 않는다. 길어지기 전에 작업 상태를
짧게 정리하고 클라이언트의 기능을 사용한다.

대화 요약은 다음 네 줄로 작성한다.

```text
목표: 현재 요청과 완료 조건.
결정: 실제로 확정된 입력·권한·작화·공정 제약.
미결: 미검증·실패·승인 대기와 현재 근거.
다음: 바로 실행할 한 단계와 상태/receipt 위치.
```

별도의 실제 작업 상태는 무시되는 `workspace/local/`에 기록한다. 기록 항목은
current job와 cut ID, source/graph/output SHA-256, receipt/prompt_id, 최근 결함·원인,
현재 전략, 실제 승인 범위, 다음 명령, 적재/readback 상태다. 실제 프로젝트의 양식이
있으면 그 정본을 갱신하고 비슷한 상태 사본을 계속 만들지 않는다.

대화 요약과 파일 기록은 다른 목적이다. compact 자체가 파일 저장·승인·목표 생성·
Git 작업을 수행한 것으로 취급하지 않는다. 재개 후에는 요약만 믿지 말고 기록된
파일/해시와 서버 상태를 대조한다. secret과 개인 대화는 인계 요약에 넣지 않는다.
