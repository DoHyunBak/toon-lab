# 완성본 PNG 무손실 압축

루트 `compress_png.py`는 Python 표준 라이브러리만 사용한다. 외부 서비스·모델·추가
오픈소스 바이너리가 필요 없다. 프로젝트 루트에서 실행한다.

```powershell
python compress_png.py "workspace/delivery/master.png" "workspace/delivery/compressed/001화 - 회차 제목.png"
```

출력 경로는 새 경로여야 한다. 원본·기존 출력·기존 압축 영수증을 덮어쓰지 않는다.
출력 PNG 옆에 `001화 - 회차 제목.png.compression.json`이 생성된다. 영수증에는
로컬 절대 경로가 포함되므로 비공개 작업 기록에 보관한다.

## 무엇을 검증하는가

- IDAT의 zlib 데이터를 level 9 두 전략으로 재압축하고 가장 작은 결과를 선택한다.
- 더 작아지지 않으면 원본 바이트를 그대로 출력한다. 감소율은 보장하지 않는다.
- 압축 해제된 필터 포함 스캔라인과 IHDR·팔레트·투명도 등 모든 비-IDAT 청크가
  동일한지 검사한다. 픽셀과 색상 프로필, 텍스트, 해상도 메타데이터를 보존한다.
- PNG 청크 CRC, zlib 스트림, 스캔라인 길이와 필터를 검사하고 디스크 출력 바이트를 확인한다.
- 전후 SHA-256·크기·해상도·감소량과 동일성 검사 결과를 JSON에 남긴다.
- APNG, 깨진 청크/스트림, 뒤에 붙은 데이터, 512 MiB 초과 해제 스캔라인은 거부한다.
  이는 전체 PNG 적합성 인증이나 작품 품질 검수가 아니다. 큰 파일은 메모리·시간이 필요하다.

색상 양자화·팔레트 변환·리사이즈·JPEG 변환·메타데이터 삭제는 하지 않는다.
메타데이터에 전송하면 안 되는 정보가 있는지는 압축 전 별도 검수한다.

## 적재 순서

1. 고지·로고·회차 제목·본문·예고 등 최종 조립을 끝내고 실제 화면을 검수한다.
2. 위 명령으로 새 출력 경로에 압축한다. 실패 시 적재를 멈추고 원본을 보존한다.
3. JSON의 동일성 결과와 전후 해시·크기를 확인한다. 이후 파일을 편집했다면 다시 압축한다.
4. 압축 PNG를 작품별 `완성본`에 최신 한 개로 전달한다. 압축 전 원본·JSON·제작 증빙은
   `백업`/기록용 버전 폴더에 보관한다. 작품별 폴더 정책을 우선하며 JSON을 완성본에 넣지 않는다.
5. Drive의 실제 원본 바이트를 다시 받아 **output_sha256 / output_bytes**와 대조한다.
   이전 회차 파일은 현행 정책에 따라 백업으로 이동하고 부모·비공개 상태·중복을 확인한다.

로컬 압축 성공은 업로드나 provider readback 완료가 아니다. 이 도구는 Drive에 접속하거나
기존 완성본을 일괄 교체하지 않는다. 원본과 압축본의 변환 관계를 최종 증빙 장부에 연결한다.
